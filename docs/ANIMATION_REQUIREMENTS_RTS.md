# REINA RTS — матрица анимаций командиров v1

**Дата:** 2026-11-02. **Статус:** проверенные ID библиотеки Meshy, но не проверенные на нашей сетке клипы. Управление — исключительно RTS-приказы. Визуальные анимации не определяют скорость/время попаданий.

## Базовый общий набор

| Приоритет | Игровое состояние | Meshy — точное имя, action_id | Примечание |
|---|---|---|---|
| P0 | IDLE | `Idle` — **0** | Цикл ожидания, все героини |
| P0 | WALK | `Walking_Woman` — **1**; альтернатива `Casual_Walk_inplace` — **613** | Команда перемещения; если клип содержит root motion, отключить его или использовать in-place |
| P0 | RUN | `Run_02` — **14**; `run_fast_3_inplace` — **659** | Быстрый марш, только по игровому приказу, не ручной спринт |
| P0 | ATTACK | `Attack` — **4** или `Draw_and_Shoot_from_Back` — **222** | Проверить тип оружия и анимацию кистей; огонь/урон рассчитывает игра/сервер |
| P0 | HIT | `Hit_Reaction` — **178** | Короткая реакция, без тяжёлого физического отбрасывания |
| P0 | DEATH | `Dead` — **8** | Одна анимация смерти; после неё состояние юнита фиксируется логикой |
| P1 | ALERT | `Alert` — **2** | Разведка и предупреждения |
| P1 | RELOAD | `Standing_Reload` — **170** | Только для командиров с оружием и механикой магазина |
| P1 | COLLECT | `Female_Crouch_Pick_Up_Place_Side` — **274**, либо `Collect_Object` — **284** | Командир подошёл к контейнеру по RTS-приказу; начисление после серверного подтверждения |
| P1 | MOVE_ATTACK | `Walk_Forward_While_Shooting` — **234**, либо `Walk_Forward_While_Shooting_inplace` — **690** | Нужен лишь если разрешаем атаку в движении |
| P1 | ORDER | `Call_Gesture` — **29** | Подтверждение команд/направления отряда |
| P1 | SCAN | `Short_Breathe_and_Look_Around` — **338** или `Alert` — **2** | Для Амины + эффекты дрона и сканирования в Godot |
| P2 | COVER | Специализированный клип после оценки механики укрытий | Не оплачивать анимацию пока укрытия отсутствуют |
| P2 | ENGINEERING | Временно `Collect_Object` — **284** или жест руки | Мира: ремонт выполняет сервер, визуально инструмент и VFX; специальный клип позже |
| P2 | STEALTH | `Sneaky_Walk` — **559** | Лира: важнее прозрачность/видимость и серверные правила, чем новый клип |
| P2 | COMMS | `Phone_Call_Gesture` — **50**, `Call_Gesture` — **29** | Рэйна: тактический интерфейс, отдача приказа |

Таблица ID сверена с официальной библиотекой Meshy (2026-11-02): https://docs.meshy.ai/en/api/animation-library. **Наличие пресета не означает, что он качественно совпадёт с нашей моделью, оружием или типом захвата.** Веб-приложение имеет собственный перечень доступности/условия тарифа.

## Специализация Лиры Восс: снайпер (зафиксировано 2026-11-04)

Дальность оружия для будущей реализации — **16** игровых единиц, после подготовки неподвижной позиции — **18** (+2); это боевой параметр, не длительность/масштаб анимации. Не использовать обычную скорострельную штурмовую анимацию как замену снайперской.

- **P0:** Idle с длинной винтовкой; Walk/Run с опущенным оружием; поднять/опустить винтовку; точное прицеливание стоя; одиночный выстрел с отдачей; перезарядка; Hit; Death.
- **P1:** прицеливание и стрельба с колена, переходы стоя↔колено, работа с разведдроном и меткой цели.
- **P2:** скрытная ходьба, разворачивание наблюдательной позиции, смена укрытия.

Для длинной винтовки проверить две руки на ложе, отсутствие пересечений локтя и корпуса и отсутствие клиппинга с короткими волосами/капюшоном. Переходы должны поддерживать сброс прицеливания при получении приказа движения. Доступность конкретных анимаций в Meshy проверять на нашем риге. Полные правила: [LYRA_VOSS_SNIPER_COMBAT_DESIGN_v1.md](LYRA_VOSS_SNIPER_COMBAT_DESIGN_v1.md).

## Что НЕ нужно в чистой RTS

- Анимации ручного прицеливания с виртуальным правым стиком, непрерывные FPS/TPS-реакции камеры.
- Отдельный набор восьминаправленного перемещения от джойстика.
- Паркур, прыжки, сложное управление от третьего лица.
- Полная дорогая лицевая анимация для каждой 3D-фигурки на карте.

**Портреты выбора и реплики:** выразительная статичная 2D-иллюстрация + опционально 2D-микроанимация глаз, рта, волос. Не нужно расходовать Meshy-кредиты на детализированную лицевую 3D-кинематику ради RTS.

## Состояния игровой логики

```
Idle -> Move -> Idle
Idle/Move -> Attack -> Idle/Move
Idle/Move -> Interact/Scan/Repair -> Idle
Any alive state -> Hit -> previous state
Any alive state -> Death (terminal)
```

**Важно:** `move`, `attack`, `interact`, `ability`, `hold`, `stop` — игровые команды, а `walk`, `shoot`, `scan` — визуальные клипы. Не привязывать авторитетную боевую экономику к событию в PNG/GLB или событию от клиента.

## Настройка и проверка в Meshy и Godot

1. Оставить оригинал `.glb` и исходное изображение. Текущий тестовый Neon Neko Cadet содержит сетку, но **нет skins/animations**.
2. Для rig: **одна модель, A/T-pose, руки отделены от корпуса, пальцы и колени читаемы**; отдельный turnaround-лист не скармливать как один персонаж.
3. Если топология плохая — Remesh; затем UV/текстуры по необходимости; после — Humanoid Rig и размещение маркеров. Smart Rig для нетипичных существ не даёт ту же библиотеку человеческих движений.
4. Сначала добавить только **Idle 0, Walk 1, Run 14**, проверить ноги, юбку, ремешки, волосы, высоту.
5. Затем `Attack 4`, `Hit 178`, `Dead 8`. Игровая скорость перемещения контролируется логикой, а не root motion.
6. Экспорт GLB с клипами; Godot `AnimationPlayer` + `AnimationTree` со StateMachine/OneShot, `Skeleton3D`; сохранить повторяемое соответствие клипов.
7. На телефоне проверить: пересечения юбки и бёдер, причёску, стопы на поверхности, переключения, idle latency, стабильность FPS.
8. Создавать следующий набор героинь только после первого успешного перехода модели через конвейер.

**Приоритет ресурсов**: первая модель Амины LOD0 ориентировочно 12–15 тыс. треугольников (проверять по файлу), LOD1 5–7 тыс., LOD2 1,5–3 тыс.; реальный бюджет определяется профилированием Android и числом одновременно видимых юнитов. Для стандартных солдат бюджет меньше.
